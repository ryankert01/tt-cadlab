Goal (started 2026-09-09): paper-style study of Palu (low-rank KV cache) on the Wormhole n300 with Llama-3.1-8B-Instruct. Headline comparison is original model on TT vs Palu(model) on TT, both perplexity and speed measured on device through one harness.

Stages: (1) functional port with existing ttnn ops, V via the MLA decode op, K reconstructed per step; (2) fused tt-metal K-reconstruction+RoPE decode kernel; (3) TT vLLM serving capacity/throughput.

Decisions: tt-metal v0.78.0 as submodule built from source (clang-20); plain-SVD uniform ranks (multiples of 32) now, Palu's full Fisher+whitening recipe on CPU fp32 in background (bf16 is ~1000x slower on this CPU); group size 1; non-paged cache in stage 1. Spec: docs/superpowers/specs/2026-09-09-palu-tt-stage1-design.md. Weights in ~/.cache/huggingface (user-owned). See [[shared-server-no-tt-data]].

Status 2026-09-10: stage 1 implemented (Tasks 1-13) on branch worktree-bright-elm-xum9. Key results on n300: identity path == stock (ppl 7.255 vs 7.254, 32/32 tokens); V-only compression is free (decode 38.8 vs 38.1 ms @1k, fits 8k ctx @batch 32 where stock OOMs at 4k); rows that reconstruct K are 2.4-9x slower in decode (stage-2 target). Uncalibrated per-head SVD is catastrophic (r96 ppl 79, r64 ppl 704). Palu's calibrated recipe (Fisher-uniform + whitening, group size 1) needs float64 whitening (layers 0-1 cond ~1e16-1e18) and at ratio 0.5 puts K at rank 32 everywhere -> still degenerate (ppl ~2400); calibrated V alone is fine (short-text ppl 13 vs 11.7). A ratio-0.7 point was added. See [[ttnn-weight-cache-trap]].

Stage 2 spec + plan written 2026-09-10 (docs/superpowers/specs/2026-09-10-palu-tt-stage2-design.md, docs/superpowers/plans/2026-09-10-palu-tt-stage2.md; 6 tasks). Design: separate op `palu_sdpa_decode` = verbatim copy of flash-decode in the tt-metal submodule (local branch `palu-sdpa` off v0.78.0, NOT stripped; envelope enforced by host asserts); per K row tile AB = lat @ [u_k | u_k T] then K_rot = A*cos + B*sin into the K CB (column-major tile order j*Sk+i). Phase 1 streams absolute cos/sin rows per chunk (checkpoint only, c=128). Phase 2 (the headline) uses chunk-relative angles for K (first c table rows resident) and rotates the QUERY by R_{-c} per chunk in fp32 on core (q R_p (k R_{s0+t})^T = (q R_{p-s0})(k R_t)^T) -- replaced the approved K-side recurrence because at the op's default chunk (512) that state is 512 KB + ~100 SFPU ops/chunk. CBs: c_4 w_rot(+T), c_9 latent, c_10 AB row block, c_12 q-state fp32 (zero tile dropped), c_13 cs, c_14 rot_step. Perplexity here is prefill-only, so decode fidelity comes from a new `palu_tt.decode_check` (64 teacher-forced steps, logits PCC). Success bar: fused == naive (PCC>=0.99), calibrated rows decode <= stock at 1k/4k, run at 8k. User must fork tenstorrent/tt-metal -> ryankert01/tt-metal and provide push creds (none on the box).
Stage-1 fact worth remembering: unpaged flash decode uses a STATIC K chunk = min(512, largest pow2 dividing S) (dynamic chunking is paged-only); with 16 q heads/chip stock uses 16-row Q tiles; HiFi4 preset has fp32_dest_acc_en=True. `mul_tiles_bcast_rows` accepts a `bcast_row_idx` on Wormhole.
